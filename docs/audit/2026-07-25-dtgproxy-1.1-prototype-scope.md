# DTGProxy 1.1 Prototype Scope

Date: 2026-07-25

Status: prototype implementation scope frozen for short-cycle delivery.

## Required For 1.1 Prototype

- One backend-independent T-Cypher, temporal semantics, physical planning, and Storage SPI path.
- `ColumnBatch` remains internal to executor/exchange code; adapters expose canonical bounded pages.
- Default DTGProxy build includes RocksDB and compiles from a fresh target directory on macOS.
- RocksDB, PostgreSQL, and Neo4j support the certified canonical persistence and migration path.
- Primary-replica and shared-nothing deployment surfaces produce equivalent certified results.
- Takeover, Sidecar restart, full-stack restart, cancellation, fencing, and bounded-memory regression
  tests fail when their requested fault or resource boundary is not exercised.
- Query-scoped compile, optimize, Storage SPI calls, sent frames, encoded/decoded bytes,
  variable-width copies, and retained-memory metrics are observable without production globals.
- Release threshold calculations for latency, TTFR, throughput, memory, network bytes, and scale-out
  are executable and fail closed when supplied observations violate the documented limits.
- External T-Cypher TTFR is measured from the real Bolt client boundary to the first decoded
  `RECORD`, with result digest and row-count identity bound to every compared observation.
- RocksDB, PostgreSQL, and Neo4j natively implement bounded CandidateScan, PropertyGather,
  AdjacencyExpand, and ChangeScan primitives while DTGProxy retains residual temporal semantics.
- Production scale-out certification uses separate 1, 4, and 8 data-node processes and fails below
  2.8x and 5.0x throughput relative to the measured one-node baseline.
- CI commands use `Cargo.lock`, exact tests reject zero-test success, and clean-break checks validate
  direct and transitive workspace dependencies.

## Deferred To 1.2

The following do not block the 1.1 prototype and must not be claimed as implemented:

- Complete end-to-end streaming from every remote Shard storage path through every blocking
  PhysicalPlan operator and Bolt cursor. DTGProxy 1.1 still measures the real external boundary and
  must not describe an upstream materialized path as internally streaming.
- Prepared physical-template caching and complete request coalescing across point/property reads.
- Process RSS, backend wait, spill, and full Shard/Sidecar/Bolt network instrumentation.

## Prototype Release Commands

```text
cargo test --locked -p cypher-engine --test direct_proxy_gate -- --test-threads=1
cargo test --locked -p cypher-engine --test system_performance_gate -- --test-threads=1
cargo test --locked -p distributed-query --features test-support \
  --test performance_regressions -- --test-threads=1
cargo test --locked -p dtgproxy --features three-backend-certification \
  --test three_backend_migration -- --test-threads=1
cargo test --locked -p gateway-node --features three-backend-certification \
  --test three_backend_deployment -- --test-threads=1
cargo test --locked -p bolt-server --test external_ttfr -- --test-threads=1
scripts/certify-scale-out.sh --nodes 1,4,8 --full
scripts/tests/check-tcypher-clean-break.sh
scripts/check-tcypher-clean-break.sh
```

Real PostgreSQL and Neo4j commands require disposable service instances and the environment
variables documented by their CI workflows. Performance threshold tests validate formulas and
fail-closed behavior; the external Bolt and process scale-out commands provide the required
real-system measurements.

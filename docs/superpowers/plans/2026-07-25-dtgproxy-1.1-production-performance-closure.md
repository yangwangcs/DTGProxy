# DTGProxy 1.1 Production Performance Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close DTGProxy 1.1 with externally measured Bolt TTFR, complete native typed primitive pushdown for every production adapter, and real 1/4/8 data-node process scale-out certification.

**Architecture:** Keep T-Cypher semantics and residual correctness in DTGProxy while adapters receive only typed, bounded Storage SPI primitives. Measure TTFR at the client-observable Bolt `RECORD` boundary, and run scale-out against independently started data-node processes rather than executor threads or mocks. Feed measurements and result identities into the existing fail-closed system performance gate.

**Tech Stack:** Rust, Tokio, Bolt 5.8 framing, tonic gRPC, DTGProxy Storage SPI, RocksDB, PostgreSQL, Neo4j, shell certification harnesses.

## Global Constraints

- The language layer is backend-independent and must not depend on row, column, KV, SQL, or native graph storage layout.
- Adapters never receive raw T-Cypher and never define temporal semantics.
- Native pushdown covers CandidateScan, PropertyGather, AdjacencyExpand, and ChangeScan for RocksDB, PostgreSQL, and Neo4j; canonical residual evaluation remains mandatory in 1.1.
- External TTFR starts immediately before sending Bolt `RUN` and ends when the first decoded Bolt `RECORD` is received; it includes the `RUN` acknowledgement and subsequent `PULL`, but excludes connection setup, handshake, and `HELLO`.
- Scale-out nodes are separate data-node processes; Tokio worker count, in-process workers, and mocks do not count as nodes.
- Certification uses fixed datasets, snapshots, queries, concurrency, and duration, and records result digest, row count, throughput, TTFR, total latency, RSS, and network bytes.
- Four nodes must reach at least 2.8x one-node throughput; eight nodes must reach at least 5.0x.
- Development runs only focused checks. The complete expensive certification matrix runs once after integration.
- Do not stage, commit, push, revert unrelated workspace changes, or modify `liblib.rlib`.

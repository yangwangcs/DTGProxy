# DTGProxy 单后端启动、三后端性能测试与优化设计

日期：2026-07-27

状态：已批准，等待书面规格复核。

## 目标

DTGProxy 的正常启动必须显式选择 RocksDB、PostgreSQL 或 Neo4j，并且只初始化所选
后端。三种后端必须在互相隔离的运行环境中分别完成可复现的正确性和性能测试。基于
基准数据识别中间件瓶颈、实施优化并复测，最终交付包含测试方法、原始数据、统计结果、
瓶颈证据、改动、收益和限制的性能报告。

在线后端迁移能力继续保留。第二个后端只能在迁移开始后按需加载，并且只在迁移状态
存在期间与源后端共存。正常运行不得预先初始化潜在迁移目标。

## 当前问题

当前实现存在两个与目标不一致的边界：

1. 单机 `dtgproxy` 入口的图配置已经指定活动后端，但 `GatewayService` 启动时仍将
   Neo4j、RocksDB、PostgreSQL 和 Sidecar 工厂全部注册到同一个 Registry。未选后端
   不一定建立实际连接，但启动边界仍然允许全部后端，并且无法证明进程只初始化了一个
   后端。
2. 分布式 Data Node 的 `BackendManager::production` 同时注册 RocksDB 和 Sidecar。
   PostgreSQL 与 Neo4j 通过各自 Sidecar 提供服务，但部署配置没有一个统一、可核验的
   “本次启动选择的逻辑后端”边界。
3. 现有论文性能准备流程要求一个运行清单同时配置三种后端和所有拓扑。该结构适合描述
   完整实验矩阵，却容易让三种后端服务同时驻留并争用 CPU、内存和磁盘，不能证明每个
   后端是在隔离条件下完成测试。

## 方案选择

### 采用：运行时单后端注册

维持统一二进制和统一 Adapter SPI，但由启动配置选择并注册一个后端。迁移命令携带的
目标配置通过受控的按需加载路径创建目标工厂。该方案改动集中、兼容现有部署形式，并能
直接证明普通运行只有一个活动后端。

### 未采用：三个后端专用二进制

分别构建 RocksDB、PostgreSQL 和 Neo4j 二进制可以提供最强的链接级隔离，但会扩大
构建、发布、部署和迁移矩阵。当前目标要求运行时只初始化一个后端，不要求从最终二进制
中移除其他 Adapter 代码，因此暂不引入该复杂度。

### 未采用：所有后端统一外置 Sidecar

这一方案能简化 Data Node，但会给 RocksDB 增加额外进程和 RPC 开销，污染本次中间件
性能测量，也会改变现有嵌入式 RocksDB 的生产路径。

## 启动配置模型

系统引入一个规范化的逻辑后端选择，允许值固定为：

- `rocksdb`
- `postgresql`
- `neo4j`

单机入口继续通过初始化命令的 `--backend` 写入选择；分布式进程配置和性能运行清单必须
显式携带同一选择。配置解析后使用强类型枚举，不在数据路径中反复比较任意字符串。

启动校验遵循以下规则：

1. 后端选择缺失、未知或与图目录中的活动 Backend Profile 不一致时拒绝启动。
2. RocksDB 选择只允许创建 RocksDB Adapter 和对应数据目录。
3. PostgreSQL 选择只允许启动 PostgreSQL Sidecar，并让 Data Node 创建连接该 Sidecar
   的 Adapter；Neo4j 同理。
4. 未选择后端不得创建连接池、数据库目录、Sidecar 进程或后台任务。
5. 启动日志和状态接口报告逻辑后端、实际 Provider、活动代数以及已加载后端集合。
6. 普通活动状态的已加载后端集合大小必须为一。

逻辑后端与 Data Node Provider 的映射保持显式：RocksDB 对应嵌入式 `rocksdb` Provider；
PostgreSQL 和 Neo4j 的 Data Node 均连接 `sidecar` Provider，但 Sidecar 进程和部署元数据
必须保留其真实逻辑后端身份，不能将二者混为同一个测试对象。

## 按需迁移

在线迁移保留现有快照、双写、索引栅栏和切换语义，但调整工厂生命周期：

1. 正常启动只创建源后端的工厂。
2. `prepare target` 阶段根据目标逻辑后端创建一个受限的迁移加载器。
3. 加载器验证目标配置、凭据引用、Backend Family、Mapping 描述和能力要求后，才打开或
   恢复目标 Adapter。
4. 双写期间状态接口明确报告源后端与目标后端，此时允许已加载集合大小为二。
5. 切换成功后关闭并释放旧源后端资源，将目标后端变为唯一活动后端。
6. 中止迁移时关闭目标资源并恢复源后端为唯一已加载后端。
7. 进程在双写期间重启时，依据持久化 Backend Slot 恢复且仅加载槽位中声明的两个后端，
   不注册第三个后端。

迁移加载器不是通用的“注册所有工厂”入口。它按目标枚举值创建一个工厂，并拒绝加载与
持久化迁移状态不一致的 Provider。

## 组件边界

### BackendSelection

负责解析、序列化和校验三种逻辑后端。它提供逻辑名称、实际 Provider 映射和是否需要
Sidecar 等只读信息，不负责建立连接。

### SelectedBackendFactory

根据一个 `BackendSelection` 创建只含一个 Provider 的 Registry 或直接创建对应工厂。
它是普通启动唯一允许使用的工厂入口。

### MigrationBackendLoader

只在持久化迁移状态或有效迁移命令存在时加载目标工厂。它验证源、目标不同，且目标与
Backend Profile 一致。

### BackendLifecycleStatus

向状态接口和测试暴露逻辑后端、Provider、代数、生命周期阶段和已加载后端集合。状态不
包含凭据或连接字符串。

### IsolatedBenchmarkRun

描述一次只包含一个后端的实验运行，包括后端、数据集、拓扑、路径、并发、消融配置、
环境指纹和输出目录。三个运行可以由总编排器顺序调度，但不能共享正在运行的后端服务。

## 数据流

普通启动的数据流为：配置文件或 CLI 选择逻辑后端，配置校验将其转换为
`BackendSelection`，选定工厂只创建一个 Adapter 路径，Replica 打开活动槽位，状态接口
发布唯一活动后端，随后才开始对外服务。

迁移的数据流为：控制面记录目标 Backend Profile，迁移加载器按目标选择创建第二个
Adapter，源快照恢复到目标，系统进入双写和索引栅栏阶段，验证一致后切换，旧源资源被
释放，状态重新回到单后端集合。

基准的数据流为：总编排器选择一个后端，启动该后端及对应 DTGProxy 拓扑，完成就绪和
数据摘要验证，依次执行 Backend Direct、Adapter Direct 和 Proxy 路径，封存结果并关闭
全部进程，然后才开始下一个后端。

## 性能实验设计

### 隔离原则

RocksDB、PostgreSQL 和 Neo4j 各自使用独立运行 ID、输出目录、端口、数据目录和进程组。
每轮开始前确认其他两种后端没有由本编排器遗留的活动进程；每轮结束后执行有界优雅关闭
并记录退出证据。不得通过杀死或修改不属于本次运行的用户进程来实现隔离。

### 测试路径

保留三条具有相同逻辑结果的路径：

- Backend Direct：执行后端原生操作。
- Adapter Direct：通过生产 Storage SPI 和固定 ReadSnapshot 执行。
- Proxy：通过持久 Bolt 连接、Gateway、T-Cypher 编译优化、分布式执行和 Adapter 执行。

比较单元必须具有相同数据集摘要、查询参数、行数和结果摘要。没有等价原生操作的工作负载
明确标记不可用，不使用语义更弱的替代查询。

### 矩阵

正式矩阵沿用已批准的论文性能协议：

- 后端：RocksDB、PostgreSQL、Neo4j，分三轮执行。
- 并发：1、8、32、64。
- Proxy 拓扑：1、4、8 个 Data Node。
- 正式预热 30 秒，测量 60 秒，每个 Cell 重复 5 次。
- Comparison：单节点下比较 Backend Direct、Adapter Direct 和 Proxy。
- Scale：Proxy 在 1、4、8 节点下测试。
- Ablation：固定代表性节点与并发，分别关闭主要优化。

调优过程中只执行明确标为 diagnostic 的短矩阵。正式矩阵在代码和环境封存后执行一次，
失败 Cell 不得被静默重试替换。

### 指标

每个 Cell 至少记录：

- 完成操作数、错误数和吞吐量；
- 总延迟与 TTFR 的 p50、p95、p99；
- CPU 时间、峰值 RSS 和网络字节；
- Gateway admission 等待、目录等待、分片扇出起止；
- Adapter 页数、读取行数、候选行数和残余过滤行数；
- Exchange 编码与解码字节；
- 查询编译、优化和执行阶段时间；
- 结果摘要、行数、环境指纹和二进制摘要。

统计汇总包括均值、中位数、标准差、95% 置信区间、Proxy 相对 Adapter Direct 的开销、
Adapter Direct 相对 Backend Direct 的开销，以及优化前后的相对变化。

## 优化方法

优化必须从实测证据出发：

1. 在未修改性能路径前完成三个后端的基线或可复现诊断基线。
2. 将 Proxy 总成本拆分为编译规划、Gateway 排队、目录等待、分片扇出、Adapter 读取、
   网络交换和结果编码。
3. 分别识别每种后端的主要瓶颈，并识别三个后端共有的中间件热路径。
4. 优先优化公共中间件路径；后端专用优化必须保持 Storage SPI 和时态语义不变。
5. 每项优化都增加正确性回归测试，并在适用时提供仅供基准使用的消融开关。
6. 使用相同数据、查询、并发和运行协议复测。
7. 只有结果摘要和行数一致、错误数为零的 Cell 才能用于收益结论。

禁止通过减少数据量、放宽时态语义、改变查询结果、跳过持久性要求或把 Candidate 结果当作
Exact 结果来获得性能提升。

## 错误处理

- 启动配置错误在打开网络监听器和后端资源前失败。
- 所选逻辑后端与 Backend Profile 不一致时，错误必须同时指出二者但不得泄露凭据。
- Sidecar 未就绪、身份不匹配或后端类型不符时，Data Node 不进入 ready 状态。
- 迁移目标加载失败不得影响源后端服务；失败目标必须显式清理。
- 双写恢复不能推断缺失的后端类型，只能依赖持久化槽位。
- 基准编排器遇到结果漂移、错误、进程异常退出、缺失指标或隔离检查失败时使 Cell 或整轮
  运行失效，不生成成功结论。
- 清理只作用于本次运行记录的进程、端口和目录。

## 测试策略

### 单元测试

- 三种后端选择的解析、显示、序列化和非法值拒绝。
- 选定工厂对每个选择只注册预期 Provider。
- 普通状态拒绝已加载集合大小不为一。
- 迁移加载器拒绝相同源目标、未知目标和 Profile 不匹配。
- PostgreSQL 与 Neo4j 的逻辑身份在共同使用 Sidecar Provider 时仍保持可区分。

### 集成测试

- 分别启动三种后端，验证未选后端没有连接、目录或 Sidecar 副作用。
- 配置选择与目录 Profile 不一致时启动失败。
- 三种源目标组合的按需迁移至少覆盖 RocksDB 到 Sidecar、Sidecar 到 RocksDB，以及两个
  不同逻辑 Sidecar 后端之间的迁移。
- 迁移成功、中止和双写重启后恢复到正确的已加载集合。
- 基准编排器按顺序运行三后端，并在开始下一轮前确认前一轮已关闭。

### 回归与性能测试

- 运行相关 crate 的单元和集成测试。
- 运行三后端 Mapping TCK 和现有两种部署模式认证。
- 使用固定诊断矩阵验证报告生成、摘要一致性和优化开关。
- 在真实后端和真实多进程拓扑上执行正式矩阵；模拟器只验证工件合同，不能作为性能数据。

## 性能报告

最终报告写入带日期的 `docs/audit/performance/` 文档，并链接封存的运行工件。报告包含：

1. 目标、范围和后端启动模型。
2. 硬件、操作系统、工具链、后端版本和代码摘要。
3. 数据集、工作负载、拓扑、并发、预热、测量和统计方法。
4. 三种后端的 Backend Direct、Adapter Direct 和 Proxy 原始及汇总数据。
5. 1、4、8 节点扩展结果。
6. 瓶颈证据与阶段分解。
7. 每项优化的代码改动、消融结果和优化前后对比。
8. 正确性与结果摘要验证。
9. 未达到预期的结果、环境限制和剩余风险。
10. 可复现命令和工件校验方法。

若当前可用环境不足以执行真实远程 1、4、8 节点正式矩阵，报告必须明确区分已经完成的
本机真实后端测量、诊断结果和未执行的正式矩阵。不得使用模拟、公式推算或进程内 Worker
替代真实测量。

## 验收标准

1. 所有生产启动入口都要求或解析一个明确的逻辑后端选择。
2. 普通运行中已加载后端集合大小为一，并且未选后端没有初始化副作用。
3. 在线迁移仅在迁移期间按需加载目标后端，完成或中止后恢复为单后端。
4. RocksDB、PostgreSQL 和 Neo4j 均能独立完成正确性与性能运行。
5. 三后端性能运行互相隔离，输入和协议一致，工件可校验和复现。
6. 至少一个有测量证据的中间件瓶颈被优化，并通过相同基准证明效果。
7. 优化前后所有用于比较的结果摘要、行数和语义一致，错误数为零。
8. 最终报告包含方法、数据、瓶颈、改动、结论和限制，并且不把诊断或模拟结果描述为正式
   性能结论。

## 非目标

- 不为每个后端拆分独立发布二进制。
- 不删除在线后端迁移功能。
- 不改变 T-Cypher 语言或时态语义。
- 不为了基准测试引入公开的生产消融 API。
- 不伪造当前环境无法取得的远程多节点结果。
